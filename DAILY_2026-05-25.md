## O que foi construído

O agente recebe a URL pública de um portal de fornecedor e executa o fluxo completo de forma autônoma:

```
URL do portal  →  descobre o formulário  →  extrai os campos  →  classifica semanticamente
→  gera dados fictícios coerentes  →  preenche campo a campo  →  navega entre etapas
→  para antes de submeter (por padrão)  →  gera relatório + screenshots
```

Tudo em um único comando:

```powershell
python app\run.py "https://portal.exemplo.com/cadastro" nome-do-portal
```

## Fase 3 — Preenchimento Automatizado

### DataGenerator (`domain/services/generator.py`)

Gera dados fictícios brasileiros coerentes entre si. O ponto-chave é a **coerência de sessão**: quando o gerador cria uma Razão Social, ele memoriza o nome e usa o mesmo domínio para gerar o e-mail corporativo no campo seguinte.

| Campo | Exemplo de valor gerado |
|---|---|
| Razão Social | Vulcaflex Indústria Ltda |
| CNPJ | 12.345.678/0001-90 |
| E-mail corporativo | contato@vulcaflexindustria.com.br |
| Telefone | (11) 99123-4567 |
| CEP | 01310-100 |
| Estado | SP |
| Inscrição Estadual | ISENTO |

Suporta 21 tipos semânticos. Se o tipo for desconhecido, gera uma palavra aleatória genérica.

---

### FormFiller (`infrastructure/browser/filler.py`)

Recebe uma página de formulário já classificada e preenche cada campo com o valor gerado. Opera dentro de iframes automaticamente usando o mesmo `frame_locator` do crawler.

**Estratégia por tipo de campo:**

| Tipo | Comportamento |
|---|---|
| `text`, `email`, `tel`, `number`, `textarea` | Limpa o campo e digita com delay de 40ms entre teclas |
| `select` | Tenta por `value` → por texto visível → primeira opção não-vazia |
| `radio` | Localiza pelo atributo `name` + `value`; fallback para o primeiro do grupo |
| `checkbox` | Interpreta `"true"`, `"sim"`, `"yes"`, `"1"` como marcado |
| `date` | `fill()` direto (inputs nativos); fallback para `type()` |
| `file` | Cria arquivo fake temporário (PDF mínimo válido ou PNG 1×1) e faz upload |

O delay entre teclas simula digitação humana e evita que portais sensíveis a timing rejeitem o preenchimento.

---

### NavigationOrchestrator (`infrastructure/browser/navigator.py`)

Coordena o fluxo multi-página. A cada iteração:

1. **Crawl** — extrai campos da página atual via `DOMCrawler`
2. **Classify** — classifica campos semanticamente via `GemmaClassifier`
3. **Generate** — gera valores para cada tipo semântico novo
4. **Fill** — preenche todos os campos da página via `FormFiller`
5. **Screenshot** — captura evidência visual
6. **Advance** — detecta e clica no botão correto para avançar

**Detecção de botões de avanço** — lista priorizada de 20+ seletores:
- Submissão final: `button[type="submit"]`, `button:has-text("Enviar")`
- Início de formulário: `button:has-text("Iniciar")`, `button:has-text("Start now")`
- Progressão: `button:has-text("Próximo")`, `button:has-text("Next")`, `[data-testid*="next"]`

Itera por todos os matches de cada seletor (não apenas o primeiro) para evitar clicar em botões fora da viewport — problema real no Microsoft Forms, que renderiza dois botões "Start now".

**Detecção de conclusão** — usa `innerText` (texto visível) em vez do HTML bruto para evitar falsos positivos com palavras como "sucesso" embutidas em bundles JavaScript. Indicadores: _sucesso, obrigado, thank you, concluído, submitted, confirmação..._

**Controle de submissão (`ALLOW_FORM_SUBMIT`):**
- `false` por padrão — o agente preenche tudo mas **não clica em Submit**
- O bloqueio é verificado **antes** da detecção de sucesso — se o botão de Submit está visível, a página não é de confirmação
- Resultado retornado: `SUBMIT_BLOCKED` — indica que o formulário estava pronto para envio

## Fase 4 — Generalização e Robustez

### PortalDiscovery (`infrastructure/browser/portal_discovery.py`)

Resolve o problema de não ter o link direto do formulário. O agente parte da URL pública do portal e encontra o formulário sozinho usando três estratégias em cascata:

**Estratégia 1 — Iframe embutido**
Verifica se a página já contém um iframe de plataforma conhecida.
Plataformas reconhecidas: Microsoft Forms, Google Forms, Typeform, JotForm, SurveyMonkey, Cognito Forms.

**Estratégia 2 — Link direto para plataforma**
Procura `<a href>` apontando para domínio conhecido. Detecta se o clique abre nova aba ou navega na mesma aba e lida com ambos os casos.

**Estratégia 3 — Botão/link de acesso ao formulário**
Tenta seletores de texto como `"Acessar formulário"`, `"Cadastrar fornecedor"`, `"Iniciar cadastro"`. Se encontrar, clica e verifica se a página destino tem iframe de plataforma.

Se nenhuma estratégia funcionar, retorna a página atual como fallback (útil quando o próprio portal já é o formulário).

---

### Suporte a SPAs — Microsoft Forms (`infrastructure/browser/crawler.py`)

O Microsoft Forms não usa `id` nem `name` nos inputs — usa `aria-labelledby` apontando para IDs compostos. Antes dessa melhoria, todos os campos voltavam como `UNKNOWN`.

**Solução implementada:**
- `_build_selector` detecta quando `id` e `name` estão vazios e usa `[aria-labelledby="QuestionId_r..."]`
- Resolve múltiplos IDs separados por espaço: `aria-labelledby="id1 id2"` → `split(/\s+/)` → usa o primeiro
- Na extração de label, prioriza o `aria-labelledby` sobre o `aria-label` genérico (`"Single line text"`) que o Microsoft Forms coloca em todos os inputs

**Resultado:** campos passaram de `UNKNOWN` para `razao_social`, `cnpj`, `telefone`, etc. com classificação semântica correta.

### CLI — Typer (`app/run.py`)

Interface de linha de comando completa. Integra `PortalDiscovery` + `NavigationOrchestrator` em um único comando.

```powershell
# Execução padrão (preenche, não submete)
python app\run.py "https://portal.com/cadastro" empresa

# Sem interface gráfica (CI/servidor)
python app\run.py "https://portal.com" empresa --headless

# Com delay entre campos
python app\run.py "https://portal.com" empresa --slow-fill

# Informando o iframe diretamente (pula a discovery)
python app\run.py "https://portal.com" empresa --iframe 'iframe[src*="forms.office.com"]'

# Habilitar submissão (somente em produção, após validar os dados)
python app\run.py "https://portal.com" empresa --submit
```
